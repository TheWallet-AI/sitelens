# SiteLens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver an independently runnable, evidence-backed GEO readiness audit application with optional Infoholder recommendations.

**Architecture:** A Next.js application orchestrates a framework-independent report core, a constrained server-side crawler, and an optional model adapter. Stream audit progress and retain reports in browser memory for download. All external website data is untrusted.

**Tech Stack:** Next.js 16, React, TypeScript, Node.js 22, npm lockfile, Zod, Cheerio, robots-parser, ipaddr.js, Undici, Vitest, Playwright, Docker. Resolve compatible secure versions before installation.

**Spec:** ../specs/2026-10-16-sitelens-design.md

## Global Constraints

- Target repository: TheWallet-AI/sitelens; product: Infoholder SiteLens.
- All repository-authored content must be English, including UI copy, comments, documentation, tests, and commit messages.
- Multilingual source evidence remains verbatim; reports and interface are English.
- Next.js 16 App Router, Node.js runtime, deployment target Node.js 22.
- Default scope: five same-origin HTML pages, depth one.
- Server-enforced defaults: two concurrent audits, two concurrent fetches per audit, 90-second overall deadline, 10-second individual request timeout, three redirects, 2 MiB maximum decoded response per page, and 10 MiB total crawl download.
- No account requirement, telemetry, database, durable queue, public report publishing, billing, or scheduled monitoring in version 1.
- No automatic website changes, form submission, booking, purchase, or report upload to Infoholder.
- Proposed MIT license was included in the approved written specification.
- GitHub creation and deployment status must be reported accurately. Creating the repository does not deploy the application.

## Review Focus

1. Malformed and encoded URLs must not reach internal networks (Task 2).
2. Compressed response expansion must obey decoded byte limits (Task 2).
3. Cancellation and provider failures must release capacity and preserve completed findings (Tasks 4–5).
4. Source text containing HTML, Markdown, or model instructions must remain inert and traceable (Tasks 3, 4, 6).
5. Partial crawl coverage and truncated output must not become false claims about missing business information (Tasks 3, 5, 6).

## Task 2: Safe HTTP Transport and Robots Policy

**Files:** src/server/crawl/url-policy.ts, transport.ts, robots.ts; tests/unit/url-policy.test.ts; tests/integration/transport.test.ts, robots.test.ts.

**Interfaces:** `validatePublicUrl(input: string): URL`; `safeFetch(url: URL, options: {signal: AbortSignal; budget: DownloadBudget}): Promise<FetchResult>`; `checkRobots(url: URL, options: {signal: AbortSignal; budget: DownloadBudget}): Promise<RobotsDecision>`. DownloadBudget is an audit-scoped atomic byte counter. FetchResult exposes final URL, status, headers, bounded decoded body, and redirect chain.
